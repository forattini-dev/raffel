## What to build

Build an adversarial fuzz harness that exercises a curated catalogue of attack vectors against every hardened surface delivered by #104, #105, #106, and #107. The harness is a separate test runner (not part of the per-feature acceptance suite) so it can be triggered as a small representative subset on every CI run and as a longer randomised job on a nightly schedule.

End-to-end behaviour: running the harness boots each adapter (HTTP, WebSocket, JSON-RPC, MCP, proxy in forward and CONNECT MITM modes), fires the catalogue against every documented sink, and asserts that the rejection / sanitisation happens at the documented layer with no leakage past the boundary.

## Acceptance criteria

- [ ] A curated fuzz catalogue covers CRLF, NUL, control characters, oversized inputs, malformed UTF-8, Unicode confusables, and HTTP header continuation tricks.
- [ ] Each hardened surface registers an integration sink against which the catalogue runs.
- [ ] The harness has two run modes: a fast representative subset for normal CI (under one minute), and a longer randomised mode for nightly.
- [ ] When a sink leaks (i.e. the malicious bytes reach the wire downstream / upstream / log), the harness fails with a clear diagnostic identifying the surface and the vector.
- [ ] Adding a new attack vector to the catalogue is a one-line append.
- [ ] The harness lives in its own test runner and does not slow down per-feature acceptance suites.
- [ ] CI configuration exposes both run modes; nightly mode runs on a separate workflow.
