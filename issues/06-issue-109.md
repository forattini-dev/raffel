## What to build

Publish the trust-boundary documentation: a guide that names Raffel's attacker model, lists the surfaces the sanitiser covers, lists the responsibilities that remain with the application developer, and documents the rejection-versus-stripping policy per sink. The guide is the artefact future security audits start from.

This slice is HITL because the doc formalises a security contract — phrasing matters, and the maintainers should review it together rather than ship it autonomously.

## Acceptance criteria

- [ ] A new guide is added under the policies / security area of the docs site (location agreed during review) covering: attacker model, in-scope surfaces, out-of-scope surfaces, per-sink behaviour (reject vs strip vs escape), and a brief worked example referencing a known historical attack of this class.
- [ ] The guide names the application-developer responsibilities explicitly: custom proxy hooks, custom resolvers, custom conditions, application-supplied logger sinks.
- [ ] The guide includes a "what to do when you find a new sink" checklist for future contributors so adding a sanitiser call is a routine code-review item.
- [ ] The existing policies / proxy / WebSocket docs cross-link to the new guide.
- [ ] Sidebar surfaces the guide.
- [ ] A maintainer review pass has signed off on the wording before merge.
